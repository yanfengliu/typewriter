# Lessons

Known traps in this repo, newest first. Add one when a problem cost real time and a later session could walk into it again: what happens, why, and what to do instead, with where the evidence is.

- **A guard that only looks when the thing it guards is on cannot see it being off.** The first trip-lock test checked the rocker's angle only `if (tw.tripLockIn)`, so the one case that mattered, the tab failing to go in, skipped the check. Condition an invariant on the situation (the carriage is past the trip point), never on the mechanism under test. Found by the trip lock's review (`docs/review-fable-5-2.md`, F22).
- **Two parts that can each block the other need a pair of switched stops, and exactly one of them must be on at every moment.** The lock comb and a key lever, the trip lock's tab and the rocker's finger: whichever is in the way first holds the other. Each pair is two one-sided stops chosen from positions in `Typewriter.lockLogic`, and a stop that waits for a part is placed where that part stands when it is switched on. Decide the pair from one position only (the carriage is past the trip point, or it is not). The trip lock at first also asked the rocker to be within 2 mrad of home before letting the tab in; a blow of 25 N or more moves the rocker further than that in one substep, so in a tie neither stop came on and the escapement tripped where it must not. A tolerance on one part's overshoot is a speed limit in disguise: sweep forces well beyond what the interface can produce. Keep such stops out of the sleep group's constraint list, or waking the group switches both on.
- **Do not run the tour walk while the tests and the build are running.** A walk stalled at step 17 (the page stopped answering) with `npm run check` and `npm run build` going at the same time; it passed twice when run alone and the cause was not found. Until it is, treat a stall under load as unproven either way and rerun the walk alone.
- **The escape wheel is not geared to the carriage going forward.** The rack drives it through a one-way ratchet, so when the carriage is stopped the wheel coasts on until a tooth meets a dog. A design that relies on "the wheel is where the carriage is" fails: a right margin stop set 0.4 of a space short of the last tooth was meant to make a trip there harmless, and the wheel simply coasted to the dog (4 of 34 timings still left the next line a column in). The same change made every return land a column in, because the pinion ratchet clicks once per full space the carriage is pushed back relative to the wheel: the carriage must overrun the first column by more than the wheel was short. Worked out in `docs/review-fable-5-2.md`, finding F15.
- **Renumbering a coordinate means moving everything measured from it.** `newSheet` set the platen angle to zero while the line pawl's latch (`state.pawlLatch`) kept the old angle; pressed during a return it flung the platen at thousands of rad/s. It now shifts the angle by whole lines together with the latch and any impact being tracked. When adding state that stores an absolute angle or position, add it there too. Guarded by `tests/typing.test.ts` ("a new sheet can be fed at any moment").
- **A stop switched on by position logic must be placed where the part is.** The comb's stop against a lever had a fixed position 20 µm short of the threshold that decides whether it applies; switched on with the comb in that gap, it moved the comb 19 µm in one substep, which is 0.76 m/s. `lockLogic` now sets the stop's position when it switches it on. Position projection turns any distance closed in one substep into velocity.
- **A scratch script that loops until the machine is idle needs a time limit, and a stopped shell command can leave its `node` running.** A `while (!tw.idle)` loop hung on a bug; stopping the background command did not kill the `node` process under it, which then held a CPU core for over an hour and made every timing measurement after it wrong. Give such loops a simulated-time limit, and if timings drift, list the `node` processes before believing them. Evidence: devlog 2026-11-11 (review fixes).
- **A failing assertion on a big object looks like a slow simulation.** `assert.equal(finger, null)` took 30 s to fail, because Node formats the whole object graph (the finger reaches every body and constraint) for the message. Compare a boolean or an id instead. Found while chasing a "40 s test" that simulated for 2 s.
- **Waking a group switches on every constraint in it.** A constraint that position logic turns on and off (the lock comb's block, the space-bar lock) is therefore wrong for a moment after any wake. `Typewriter.lockLogic` runs last in the pre-step hook, after fingers and the typist may have woken parts, so the solver never sees the stale state; a stop applied at the wrong position yanks the part there in one substep. Put any new switched constraint under the same rule.
- **A pusher that should also hold needs a stop at the end of its stroke, and must let go on the way back.** The backspace pawl only pushed, so with a firm press, or near the right margin where the mainspring pulls least, the carriage coasted a second tooth back. Coupling pawl and rack both ways fixed that but trapped the key down once the carriage had settled on its tooth. The wedge at the bottom of the stroke (`backWedge`) does both. Guarded by `tests/typing.test.ts` ("backspace moves the carriage exactly one column"); the old test only tried mid-line with one force, so sweep position and force when a mechanism works against a spring.
- **A snapshot test must be shown to fail.** The first version passed with half the saved state deleted. `tests/keystroke.test.ts` ("snapshots are complete at awkward moments") now drives the machine elsewhere before restoring and compares everything bit for bit; each saved item was removed in turn to see the test fail. When adding state to `Typewriter`, add a moment that depends on it and repeat that check.
- **The in-app browser pane throttles when hidden.** Hidden, it runs `requestAnimationFrame` at about 2 fps or not at all (no frame in 24 s on one occasion, so a tour step started there never finished and looked like a hang) and JavaScript several times slower, and a screenshot can show a frame from before your last script ran. Timing, frame rate and "does it keep up" checks must be done in a foreground or headless browser; the Playwright CLI headless on this machine uses the GPU (ANGLE D3D11) and ran this app at 175 fps. In the pane, drive frames yourself with `app.tick(1/60)` and wait a few seconds before a screenshot. Evidence: devlog 2026-11-11.
- **The typist has state the machine snapshot does not hold.** `Typist` remembers that it is holding Shift, which typebar is in flight and whether a return is under way. After `Typewriter.restore` those fingers are gone: call `typist.reset()`, not `clear()`, or the next capital waits forever for a Shift it thinks is already down. Guarded by `tests/typing.test.ts` ("after the machine is restored mid-capital"); red without the reset: stalls with 2 pending after 5 s.
- **Contact flags are state.** `Constraint.active` and `.force` are from the last substep and are read by pre-step logic (a finger decides it has "landed" from them). A snapshot saves them and a restore puts them back; leaving the old ones in place made a strike begun after a restore from mid-impact lift off at once, and merely clearing them makes a replay differ by one substep. Guarded by `tests/keystroke.test.ts` ("restoring from the middle of an impact", "snapshots are complete at awkward moments").
- **Do not model the type impact with XPBD compliance.** Implicit integration damps a 0.3 ms contact numerically (restitution 0.40 instead of 0.55 at 25 µs). Elastic contacts are explicit forces (`Constraint.stiffness`). See `docs/physics.md` section 2 and `tests/solver.test.ts`.
- **A heavy body stopped through light ones needs a direct constraint.** Gauss-Seidel passes the carriage's momentum through the gram-sized wheel and dog a few percent per substep. `holdLoose`/`holdFixed` state the chain's consequence on the carriage itself. Tried and rejected: treating a dog on its stop as pinned (it chattered at the threshold and the carriage buzzed at rest).
- **The escape wheel must not turn backward during carriage return.** With a free wheel the loose dog's spring kicks it back and the carriage settles one column off. The retaining pawl (`backCheck`) and a margin stop that overruns the first column by more than the pawl's backlash fix it; a backlash limit from dog and tooth thickness cannot work, because the loose dog then no longer fits behind the held tooth.
- **Outer typebars reach a dead centre unless each heel is clocked to its own link.** A single heel angle for all 44 bars left the end bars unable to reach the platen. `buildKey` in `src/sim/layout.ts` solves the angle per key.
- **Shell tooling on this machine.** A directory named `build` is write-protected for the agent tools (use another name); a doubled backslash in a heredoc loses one level on the way to the file (so a script that builds source text from it writes a real newline where an escape was meant): put strings with escapes into files with the Edit tool; `tsx -e` and long inline scripts are fragile, put scripts in the scratchpad and run them.
